# 系统架构

## 边界

三角洲战绩本是 Windows 本地桌面程序。正常数据流为：

```text
电脑版微信中的官方小程序登录态
  -> 本地腾讯接口客户端
  -> 分账号缓存与偏好
  -> 回环 HTTP 服务
  -> pywebview 桌面页面
```

默认桌面同步不会把登录态或战绩上传到项目服务器。生产服务器承担下载官网、版本清单、版本化发布文件，以及一个独立配置的可选共享页。版本化二进制由 Nginx 静态发送；页面、清单、兼容跳转和共享接口由 `shared_server.py` 提供或回源。

## 组件

| 组件 | 职责 |
|---|---|
| `launcher.py` | 单实例检查、选择 `current.json` 指向的 App、启动握手、更新激活和失败回退 |
| `friend_client.py` | 启动动态回环端口、创建 pywebview 窗口、桥接应用内更新与系统操作 |
| `stats_server.py` | 本地页面和 JSON API、筛选、账号管理、同步任务与官方小程序拉起 |
| `delta_api.py` | 腾讯 AMS 请求、错误分类和繁忙重试 |
| `delta_data.py` | 两种玩法的数据归一化、详情补齐、缓存、筛选、汇总和游戏时段识别 |
| `auth_registry.py` | 多账号保险箱、账号状态机、DPAPI 凭证和兼容镜像 |
| `app_updater.py` | 清单解析、断点下载、校验、解压和 pending 请求生成 |
| `shared_server.py` | 可选共享页、上传接口、下载官网和旧下载入口兼容 |

## 账号与登录态

账号 ID 是 `账号类型:OpenID` 的 SHA-256 前 24 位，不直接暴露 OpenID。微信区和 QQ 区账号使用同一个本地保险箱，但凭证、缓存、原始详情和偏好互相隔离。

| `auth_state` | 含义 | 是否允许尝试同步 |
|---|---|---|
| `valid` | 最近一次验证成功 | 是 |
| `pending_verification` | 定向恢复一个已有账号时，同账号新凭据因繁忙或网络问题尚未验证 | 是 |
| `unverified` | 凭据完整但尚无确定验证结果 | 是 |
| `expired` | 腾讯明确拒绝登录态 | 否，缓存仍可查看 |
| `incomplete` | 凭据缺少该区服所需字段 | 否 |
| `missing` | 仅有账号与缓存，没有凭据 | 否 |

只有明确的腾讯拒绝会把状态写为 `expired`。繁忙、网络和未知错误不会把原有凭据误标为过期；定向恢复时若候选身份与已有账号一致，同账号新凭据会保存为 `pending_verification`，供后续有限验证继续使用。普通“读取当前账号”失败不会把未绑定候选写到当前账号。

认证恢复与同步失败使用统一字段：

| `error_kind` | `retryable` | `auth_invalid` | 处理 |
|---|---:|---:|---|
| `expired` | false | true | 当前凭据不可用；引导用户在电脑版微信重新打开小程序并重读账号 |
| `busy` | true | false | 保留登录态，稍后重试 |
| `network` | true | false | 保留登录态，检查网络后重试 |
| `auth_missing` | true | false | 尚未发现完整小程序登录态；允许用户显式拉起官方小程序并等待候选 |
| `unknown` | false | false | 显示实际异常，不推断登录失效 |

`-108 / 访问人数太多`、HTTP `429/502/503/504` 和对应繁忙文案归为 `busy`。带 HTTP 响应但不属于上述类别的错误归为 `unknown`，不会伪装成本地网络故障。

`error_kind=expired` 是一次请求对“当前凭据不可用”的分类，本地凭据缺失、不完整或无法加载时也可能出现；它不等于保险箱已经持久化为 `auth_state=expired`。只有腾讯 AMS 明确拒绝才会把账号状态写成 `expired`。其它本地路由仍可能只返回普通 `error` 字段。

登录态处理分为两条独立契约。首次没有账号且普通导入返回 `auth_missing` 时，用户显式点击“刷新登录态”后才拉起官方小程序；程序轮询安全候选摘要，只选择最新候选，并携带该候选 ID 定向导入，验证成功后添加、激活并自动同步。腾讯繁忙对同一 revision 只做有限验证；网络、超时和本地操作占用按退避继续，不会被当成登录过期。

已有账号恢复始终绑定发起操作时的账号 ID。程序等待电脑版微信写入候选凭据，并只对同一账号执行恢复导入和验证。同账号新凭据验证成功后保存为 `valid` 并自动刷新战绩；遇到繁忙或网络问题时可保存为 `pending_verification`，但不会把旧凭据误标为过期。检测到其它账号不会覆盖或激活，关闭和超时也不会串改账号。

`os.startfile` 成功以及接口返回 `direct:true` 只表示固定直达请求已经交给 Windows，不证明微信已经显示目标页面。直达请求抛出启动错误时才回退到普通 `weixin://`；页面是否真正到达小程序仍以随后能否检测到目标账号的新凭据为准。

## 同步与缓存

同一时间只允许一个账号导入、管理或同步操作。线程锁负责当前进程，`operation.lock` 负责跨进程；重复点击不会启动多个前端同步任务。

同步按烽火和全面两个列表抓取，再按玩法补详情。单个详情失败不会丢弃已经成功的数据；失败项记录退避时间，后续同步再尝试。腾讯繁忙只对关键列表请求做带抖动重试，并共享有限等待预算。

本地数据根目录为 `%LOCALAPPDATA%\DeltaForceIntelAssistant`：

```text
account_vault.dat                 # DPAPI 加密账号保险箱
account_vault.bak.dat             # 上一次完整保险箱
miniapp_auth.dat                  # 当前激活账号的旧模块兼容镜像
accounts/<account_id>/cache/matches.json
accounts/<account_id>/cache/raw/
accounts/<account_id>/preferences.json
logs/{desktop,launcher,server}.log
```

选择仅缓存账号时会移除当前兼容镜像，但不会删除其它账号凭证或历史缓存。卸载安装版也不会删除该数据目录。

## 玩法与统计

`sol` 表示烽火地带，`mp` 表示全面战场。顶层页面和汇总保持分离；`all` 只作为旧接口兼容值，不提供混合业务总览。

- 烽火平均 KD 使用筛选结果中的总干员击杀除以总死亡；失败撤离计一次死亡，成功撤离计零次。
- 烽火队友接口没有入场成本或官方净收益，好友净收益保持不可用，不能用带出价值冒充。
- 全面 KD/KDA 使用逐局官方击杀、死亡和助攻；字段缺失不参与对应指标，零死亡显示无穷。
- 助攻和救援是全面专属字段。官方零值保留，未知值显示为缺失。
- 全面详情只展示腾讯实际返回的玩家集合，不宣称是完整 64 人记分板。

好友筛选的 `any` 表示任一选中好友在场，`all` 表示全部选中好友同时在场。多选游戏时段按离散区间并集筛选，再与手动日期范围取交集。

游戏时段按开局时间排序；如果下一局开局距离上一局结束超过 60 分钟，则开始新时段。时段 ID 是首局 ISO 时间。`profit_matches` 是该时段内全部烽火局数，不是收益字段覆盖率；`net_profit` 只汇总烽火局，纯全面时段返回 `null`。当前共享页尚未返回这两个本地字段，见 [路线图](roadmap.md)。

## 可选共享

`remote_sync.py` 是独立 CLI，不会随桌面同步自动运行。它只读取当前账号，先校验缓存的 `account_id`，再把整理后的逐局战绩通过 HTTPS Bearer 上传到私密共享服务；登录令牌不会上传。

共享服务保存玩家名称、更新时间和逐局数据到 SQLite。它与本地页面复用部分筛选语义，但不是本地账号保险箱或同步链的一部分。

更新与安装布局见 `update-protocol.md`，接口契约见 `integration-guide.md`。
